Your Node.js server does not need more workers

Ilia Sokolov·8 min read

Adding processes is the reflex answer to a slow server. It hides the problem. Most of the time, one request is synchronously doing something expensive, and every other request is simply standing behind it.

The event loop runs your JavaScript on a single thread. Anything that blocks that thread for longer than a few milliseconds, a synchronous file read, a large JSON.parse, a regex that backtracks, stalls every other request behind it.

No matter how many CPU cores the machine has, one paused loop is one paused server.

Profiling usually finds the same three culprits: parsing payloads that could be streamed, sorting arrays that could be indexed, and calling a synchronous API inside a hot path. Each one is a one-line fix and each one is invisible in average latency.
